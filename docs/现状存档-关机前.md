## 3. 没做完的（明天从这里挑）

### 3.1 三个 M8 老测试在真机上跑不通 —— 已知信息（别从零重查）

**它们与昨天的改动无关**，而且**失败发生在"打开编辑页"这一步**，即产品的下一页根本没进去：

```
.shots/m8-wheel-phone.txt   → could not reach the editor (title=''); the wheel is not on screen
.shots/m8-editor-phone.txt  → could not reach the alarm editor
```

两个测试都是点列表页的 `.fab`（新建）进编辑页，`title=''` 说明**当时连列表页的标题都不在**，
也就是 **app 不在可用状态**（前一个测试刚跑完，页面停在别处/没到前台）。
我随后**单独**跑 `t-wheel.py`，它**顺利进了编辑页**（`page: '新建闹钟'`，滚轮 72/180 个节点都对），
但卡在下一处：

```
[FAIL] a 48px drag advances exactly one hour: 23  (want 22)
       could not spin to 23; stuck at '22'
```

→ **判断（未证实）**：`verify-phone.py` 连跑三个测试之间**缺少"回到列表页并确认到位"的一步**；
而真机 CDP 拖动**一格位移是否累积**也需要单独查（模拟器上同一测试全绿）。
→ **明天第一件事**：给 `verify-phone.py` 的每个测试前加"确保在列表页"的断言，再单独跑一次 `t-wheel`，
看 48px 拖动是**时序**还是**真回归**。**在定性之前不要把它当成产品 bug。**

### 3.2 `t-multiselect.py` 的夹具风险（真机上会删数据）

它"按 DOM 找自己建的行"清理，但删的是**一切被勾选的行**；标签没匹配上/行没渲染出来时会删到别人的行，
而且**删了什么没有断言兜底**。它历史上就有时序问题（[M8](M8-STATUS.md) §9.0）。
**修法**：按 label 取 id → 按 id 删 → 断言"待删集合里没有非自测行"（`t-batch-holiday.py` 现在就是这么做的）。
**在有兜底之前，不要对真机跑它。**

### 3.3 `verify-phone.py` 的监控缺口

它只比对 `alarms` / `alarm_groups` 的**条数**。昨天手机上的 `snooze_enabled` 从开变关，它**完全看不见**。
**修法**：把 `settings` 的 `snooze_enabled` / `volume_key_action` / `time_format` 也纳入前后对比。

### 3.4 昨天没动的（交接页 §2 的 1~6 项）

AC-12 被回收后仍响、AC-3/AC-4 暂停窗口、AC-5 临界点、AC-2 节假日抽查、AC-16 深浅色截图、AC-17 200 个闹钟耗时。

**一条需要注意的本机配置**（2026-10-02 已由用户改掉）：这台机器的**全局** git 里原本有一条重写规则

```
url.https://github.com/.insteadOf = git@github.com:
```

它会把 SSH 地址改写成 HTTPS —— 所以第一次推送实际走的是 **HTTPS + Windows 凭据管理器**，
而不是用户配好的 SSH 公钥（SSH 本身一直是通的）。用户已执行
`git config --global --unset url.https://github.com/.insteadOf` 删掉它；
删除后实测 `remote` 为 `git@github.com:...`，并且在 `BatchMode=yes`（完全禁止交互、只允许密钥认证）
下 `git ls-remote origin` 依然成功，**说明现在确实在用 SSH 公钥**。
（全局还有一条 `url.https://.insteadOf = git://`，与 GitHub 无关，没动。）

**另外记一条给下一个会话的**：仓库里**没有** `gradlew`（项目一贯用全局 `gradle`，理由见 README），
也**没有** `android/app/src/main/assets/public/` —— 新克隆下来直接 `gradle assembleDebug` 会得到一个
WebView 空白壳，必须先 `npm install && npm run web:build && npx cap sync android`。README 的构建一节写了这件事。
