## 一、根因：一行 12/24 小时制混用

滚轮的时间换算函数 `hourFromIndex()` 把"滚轮下标"按 **12 小时制**换算成小时，但在 **24 小时制**下也被照用了。
你的手机是 24 小时制（出厂默认），于是：

| 滚轮下标 | 它算出的小时 | 你看到的现象 |
|---|---|---|
| 0 ~ 11 | 0 ~ 11 | 正常 |
| **12** | **0** | 滚轮跳回 00 —— 这就是你说的「**只能拖到 11 点，12 点及之后无法选择**」 |
| **13 ~ 23** | **25 ~ 35** | **没有任何一项能匹配**，整列都变成灰字 —— 这就是你第二张图 |

而"灰字就存不了"是同一个原因的第二步：小时变成 26 之类的值时，原生侧的时间构造会抛异常：

```
E AlarmHub/Bridge: java.time.DateTimeException: Invalid value for HourOfDay (valid values 0 - 23): 26
      at java.time.LocalTime.of(LocalTime.java:292)
      at java.time.LocalDate.atTime(LocalDate.java:1843)
```

**旧版本把这个异常吞掉了**（异常逃出点击处理函数，变成"未处理的 Promise 拒绝"，屏幕上什么都不显示），
所以表现就是"点了保存没反应"。

**你观察到的"灰字＝存不了、黑字＝可以"，第一次就把这两个问题连成了一条线** —— 那是我从代码里看不出来的关联。

### 为什么之前的验证没发现

M1b 我在浏览器里审、M6 我用 DevTools 驱动，**两次都是"点某个数字"来选时间**，
而且从没点过 12 点以后的刻度。`hourFromIndex` 只在下标 ≥ 12 时出错，所以这条路径一次都没被走到。
