# 真机复验：本轮没能做（手机掉出 adb）

**结论：本轮三项改动都还没有真机复验。** 不是失败，是手机根本不在 adb 上 ——
`tools/verify-phone.py` 在第一步就按设计停了（它区分"线没插好"和"USB 模式不对"，这次报的是后者）。

## 实测原文

```text
== 1. is the phone on adb? ==
List of devices attached
emulator-5554	device

Windows 能看到手机（Xiaomi 14），但 adb 看不到它。
请在手机上：① 解锁并允许「USB 调试」弹窗；② 下拉通知栏把 USB 用途改成「传输文件」；
③ 确认 开发者选项 → USB 调试 还开着。这不是数据线的问题。
```

## 我按交接页的已知做法试过的三步（都没救回来，别再重复试）

| 动作 | 结果 |
|---|---|
| `adb devices` 直接看 | `b9026932` 不在列表里（**会话开始时它还在，是中途掉的**） |
| `adb -s b9026932 shell echo ok` | `device 'b9026932' not found` |
| `adb kill-server` + `adb start-server` | 它**出现了一次，状态是 `offline`** —— 说明 USB 那层还在，是 adb 会话建不起来 |
| `adb -s b9026932 reconnect` | `reconnecting b9026932 [offline]`，然后设备又消失了 |

所以这次连"offline"都没留下，只能从手机那一侧恢复。

## 用户需要做的（三选一，按顺序试）

1. 手机上确认 **开发者选项 → USB 调试** 还开着，并在弹窗里点「允许」（HyperOS 会在息屏/重插后把接口关掉）；
2. 下拉通知栏，把 USB 用途从「仅充电」改成「传输文件」；
3. 拔插一次数据线。

恢复后要跑的两条（**一条命令**，脚本自己构建、逐字节核对安装、比对前后数据、跑三个 UI 测试）：

```powershell
. .\tools\env.ps1
python tools\verify-phone.py                    # 三个 M8 UI 测试，约 10 分钟
python -u .shots\t-batch-holiday.py --device b9026932 --dpr 2.75 --top 0 --via cdp
```

第二条是本轮新写的，覆盖**新增的两处**（多选栏「启用 / 停用」、设置页「节假日数据」行）；
它在模拟器上 22 项断言全绿，在真机上走 CDP 触摸通道。

**通知栏贪睡文案**（第 7 项）需要一次**真实响铃**才能看：手机上建一个 1 分钟后的闹钟 →
等它响 → 拉下通知栏看那一行。四种情况该看到什么：

| 情况 | 该看到 |
|---|---|
| 贪睡开着（默认） | `未分组 · 贪睡 10 分钟（还剩 3 次）` |
| 设置页把「贪睡」关掉再响 | `未分组 · 贪睡已关闭` |
| 只关掉这一条闹钟的「贪睡」 | `未分组 · 贪睡已关闭` |
| 贪睡次数用完后再响（重响） | `未分组 · 已无贪睡次数` |

> 第 2 行就是用户当初报的那个 bug（全局关了贪睡，通知还在推销贪睡）。
> 顺带说一句：这一条**只能在手机上看**，因为通知栏正文在模拟器上是靠 `dumpsys notification` 读的，
> 而手机上的读法要动 UiAutomation（这台 Android 16 上会把 system_server 卡死），所以真机确认只能靠眼睛。
