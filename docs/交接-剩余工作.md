### 7.2 第 7 项 · 通知栏贪睡文案

**改法**：`RingRequest.from` 里 `snoozeEnabled = alarm.snoozeEnabled && settings.snoozeEnabled`，
`canSnooze` 成为唯一判据；`RingActivity.render()` 里那句手写的 `&& snoozeEnabled` 删掉了，
通知的 `snoozeHint` 也只读这一个字段。**两个开关只在一处合并**，下游没有任何消费者需要记得它们有两个。

**四种状态的实测原文**（`.shots/t-notification-snooze-emulator.txt`，从 `dumpsys notification` 读的）：

| 状态 | 开关 | 通知正文 |
|---|---|---|
| A | 闹钟开 / 全局开 | `未分组 · 贪睡 10 分钟（还剩 3 次）` |
| B | 闹钟开 / **全局关** | `未分组 · 贪睡已关闭` ← 原来的 bug |
| C | **闹钟关** / 全局开 | `未分组 · 贪睡已关闭` |
| D | 次数用完（重响） | `未分组 · 已无贪睡次数` |

**过程中修掉了自己写出的第二处假话**：合并之后 B、C 两态会走进原来的兜底文案
「已无贪睡次数」—— 那是在说"次数用完了"，而这两个用户的次数一次都没用过。
改法是让通知把三种情况分开说（开着的、用完的、关掉的），并且**加了状态 D 把"用完"那条分支钉住**，
否则它有可能变成死代码而没人发现。

**两条踩坑记录**（都值得下一个会话知道）：
- 状态 D **必须用贪睡重响（`--as snooze`）来测**，不能用新鲜响铃：新鲜响铃会按设计清空计数
  （`AlarmReceiver.startRing` → `clearSnoozeCount`），所以新鲜响铃显示「还剩 3 次」是**对的**。
  第一版测试用新鲜响铃，报了一个产品缺陷，其实是测试不懂产品。
- 一次性闹钟在**"新建默认响铃后删除"开着**的设备上，第一次关闭就会把自己删掉，
  于是 B、C 两态**根本没有响**，两条否定式断言"通过"了 —— 因为压根没有通知。
  现在测试会断言 `ringStarted=true` 且通知真的存在，缺一不可。

### 7.3 第 8 项 · 两个死 API 接线

**`batchUpdateAlarms` → 多选栏的「启用 / 停用」**（`.shots/t-batch-holiday.py`，22 项断言全绿）：

```text
[OK ] three rows ticked: 3
[OK ] the bar reports the batch before it runs: '3 项中 3 项已开启'
     AlarmHub/Scheduler: recomputeAll: 3 stored, 0 registered, zone=GMT
[OK ] the batch cost exactly one recomputeAll, not three: 1
[OK ] all three are now disabled in the database: 3
```

```text
正常：  2025–2026 年                     （灰）
降级：  2025–2026 年 · 本年未覆盖        （警告色 rgb(255,181,71)）
```

降级态是用**模拟器的时钟拨到 2027** 造的（`getHolidayDataInfo` 每次调用都算 `coversYear(今年)`），

1. **夹具残留会伪装成十几个产品缺陷**：一次中途失败留下的行会让下一次的"数据库长了 3 行"看到 7 行，

2. **清理函数自己坏掉时最危险**：`listAlarms()` 返回的是**信封对象**（`{alarms:[…]}`）而不是裸数组，
   我第一版对它调 `.map` 抛异常，异常被"有没有残留"那句判断吞掉 —— 于是它报告"没有残留"，
   而库里躺着两行。**现在已经改成读不到就抛错**。
3. **断言要写契约，不要写文案**：`全选/取消全选` 的文案与行为取决于"当前已经勾了什么"，
   我原来把文案写死，于是报了一个产品缺陷。现在断言的是方向（读它给什么，点完就该得到相反的结果）。
   顺带把 `t-multiselect.py` 里那条偶发（`the view shrank too`，M8 §9.0 记过的同一类）

### 7.5 顺手修掉的一个真工具 bug（`ui-drive.eval()`）

`ui-drive.eval()` 对**任何返回对象的表达式**都返回字符串 `'{'`。它骗过我的三次具体表现：

1. 以为页面有语法错误（`({a:1})` 回 `{`）；
2. 以为从控制台打的插件补丁没生效（其实是读取层坏了，我当时甚至写了"补丁后直调"的探针）；
3. 以为节假日行的降级分支没实现（其实降级态一直是好的，只是读不出来）。

**根因**：`cdp-probe.js` 会把对象**多行美化打印**，再追加自己的尾巴；`ui-drive.eval()` 拿整段去
`json.loads` 失败后兜底"取第一行"，而第一行就是 `{`。**修法**：先按 `--- page console problems ---`
切掉尾巴，再解析；并对 `'{'` / `'['` 这种"永远不可能是真值"的结果**显式报错**。
钉住它的探针是 `.shots/probe-eval-guard.py`（对象、数组、嵌套、字符串、噪声五组用例全绿），
`docs/STATUS.md` §1.1 #24 有完整记录。

> 顺带记一条**本质上是歧义、不要试图消除**的东西：`cdp-probe.js` 打印字符串时是**原样**输出
> （`console.log(value)`），所以"页面打印了文本 `{"a":1}`"与"页面返回了对象 `{a:1}`"的**输出字节完全相同**，
> 两者都会解析成 dict。需要区分时，让表达式自己加前缀，而不要指望传输层保住它看不见的类型。
